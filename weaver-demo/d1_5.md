### 🕒 第 5 小時：利用 Jinja2 模板自動生成文件

#### ⚙️ 第一階段：模板驅動開發與 Weaver 配置 (15 分鐘)

**【教學目標】理解 Weaver 如何透過 Jinja2 引擎與配置檔處理 YAML 數據。**

* **為什麼需要模板？**
  Weaver 本身並不預設產出任何特定格式的程式碼或文件，而是扮演一個「數據處理引擎」的角色。它會讀取你寫好的 YAML 規格，然後依據你提供的 **Jinja2 模板** 來渲染出最終產出物（例如 Markdown 說明文件、HTML 或程式碼）。
* **探索 Jinja2 模板中的資料結構 (Context)：**
  講師展示在 Jinja2 模板中，Weaver 提供了豐富的資料變數與輔助方法：
  * **資料獲取：** 可以透過 `ctx.attributes` 取得所有屬性，或是用 `ctx.metrics` 取得所有指標。
  * **命名轉換神器：** Weaver 內建了強大的字串轉換方法，例如使用 `attr.name | screaming_snake_case` 將屬性轉為大寫底線分隔的常數命名，或是 `attr.name | pascal_case` 轉為大駝峰命名。
  * **自動格式化註解：** 使用 `attr.brief | comment(indent=4)` 可以直接將 YAML 裡的簡短描述轉換成縮排格式正確的程式碼註解。
* **Weaver Configuration (配置檔) 解析：**
  講解如何控制輸出的檔案數量。透過設定檔中的 `application_mode` 參數：
  * 設定為 `single`：會將所有的屬性群組塞進同一個模板，產出「單一檔案」（例如一份包含所有訊號的完整 README）。
  * 設定為 `each`：會針對每一個命名空間（Namespace）或群組，分別獨立產出多個檔案。

#### 📦 第二階段：現成模板應用 (10 分鐘)

**【教學目標】站在巨人的肩膀上，直接應用社群已建立的標準模板。**

* **避免重複造輪子：**
  雖然自行撰寫 Jinja2 模板可以達到 100% 的客製化，但初期可能會覺得學習曲線稍高。講師介紹 OpenTelemetry (OTel) 社群及專案中已經準備好的現成開源模板。
* **社群現成模板清單：**
  * **Java 與 Go 語言模板：** 用來生成各語言專屬的強型別 (Type-safe) 常數與結構體。
  * **OTel Demo Markdown 模板：** 專門用來生成易於閱讀的 Markdown 規格文件，可以直接放到 GitHub Wiki 或轉換至 Confluence 上供團隊查閱。
  * *實作準備：* 講師引導學員從官方 GitHub 範例庫中下載或準備一份基礎的 Markdown 模板以供接下來的實作使用。

#### 📄 第三階段：文件生成實作 (Generate) (20 分鐘)

**【教學目標】動手實作，體驗「一鍵生成文件」的震撼。**

* **實作演練：生成系統遙測規格書**
  請學員使用前兩個小時所寫的 `telemetry-schema` (包含訂單支付微服務的 YAML)，搭配剛下載的 Markdown 模板來生成文件。
* **執行指令：**
  在終端機中輸入以下指令：

  ```
  weaver registry generate \
  --registry ./telemetry-schema \
  --template ./templates/markdown
  ```

  *(備註：`--template` 參數不僅支援本機路徑，也可以直接指向遠端的 GitHub 儲存庫網址。)*
* **成果展示與驗證：**
  學員打開生成的 Markdown 檔案，將會看到系統自動排版好的表格，裡面清晰列出了 `payment.process` 的 Span、`payment.amount` 指標、資料型別、單位以及完整的文字描述。

  * **核心價值重申：** 這樣一來，開發團隊、SRE 與 PM 就能永遠對著同一份「絕對精確、不會過時」的文件進行溝通。

#### 📝 第四階段：使用 `update-markdown` 進行局部更新 (15 分鐘)

**【教學目標】學習如何將自動生成的內容無縫嵌入到現有的人工編寫文件中。**

* **情境痛點：**
  有時候我們不需要生成一整份全新的檔案。例如，專案的 `README.md` 裡面已經寫了滿滿的系統架構介紹與安裝步驟，我們 **只希望更新 README 裡面的「遙測指標表格」區塊** ，而不覆蓋掉其他人工撰寫的內容。
* **局部更新指令：`weaver registry update-markdown`**
  Weaver 提供了專門更新 Markdown 的便捷指令。
* **實作演練：**
  1. 講師請學員在現有的 `README.md` 中，加入特定的 **標記 (Markers)** 。這些標記用來告訴 Weaver：「請把模板生成出來的表格，精準地貼到這兩個標記之間」。
  2. 執行 `weaver registry update-markdown` 指令。
  3. 觀察結果：學員會發現除了標記區塊內的遙測表格被更新成最新版本外，`README.md` 中的其他手寫內容都完好無缺。
