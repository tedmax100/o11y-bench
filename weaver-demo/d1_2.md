### 🕒 第二小時：Weaver 環境建置與核心工具概覽

#### 🛠️ 第一階段：Weaver 環境建置與安裝選項 (15 分鐘)

**【教學目標】帶領學員依據自身習慣選擇並完成 Weaver 工具的安裝。**

* **安裝方式介紹：**
  Weaver 是一個命令列工具 (CLI)，官方提供了非常彈性的安裝選項：
  1. **預先編譯的二進位檔 (Pre-built binaries)：** 官方的 Release 頁面上提供了適用於 Linux、Windows 與 Mac 的安裝檔，適合想要直接在終端機使用的開發者。
  2. **Docker (推薦懶人法)：** 如果不想污染本機環境，或是想避免作業系統相依性問題，直接拉取官方的 Docker Image 執行是最快的方式。
  3. **從原始碼編譯 (From source)：** 適合想要深度客製化或貢獻原始碼給開源社群的進階使用者。
  4. **CI/CD 自動化整合 (GitHub Actions)：** 若要在管線中使用，官方提供了 `setup-weaver` Action，可以直接寫入 GitHub 工作流程中，無縫幫你完成環境配置。
* **實作小考驗：** 講師在此階段請全體學員擇一方式安裝，並在終端機輸入 `weaver --help` 或查看版本，確認環境皆已就緒。

#### 🔄 第二階段：Weaver 四大核心工作流 (Weaver Flow) (20 分鐘)

**【教學目標】用直觀的流程圖解析 Weaver 的運作機制，讓學員知道「我們到底要用它做什麼」。**

講師將介紹 Weaver 標準的「四部曲」工作流：

* **步驟一：建立 Schema (Create Schema)**
  * 這是所有事情的起點。你必須將應用的追蹤 (Spans)、指標 (Metrics) 與日誌 (Events) 寫成  **YAML 檔案** 。
  * 這些檔案會被統一放在一個特定的資料夾（例如 `telemetry-schema/`）。在這裡，你要定義命名規範、度量單位以及範例格式。
* **步驟二：準備模板 (Create Templates)** *(選填)*
  * Weaver 本身不自帶強制的產出物，它依賴 **Jinja2 模板引擎** 來發揮魔法。
  * 你需要準備模板，告訴 Weaver 如何把 YAML 翻譯成 Markdown、HTML 或 Go/Java 的應用程式碼。社群裡已有許多現成的模板可供直接套用。
* **步驟三：自動生成產出物 (Generate Files)**
  * 把「YAML」送進「模板」，Weaver 就能幫你一鍵生成系統的規格說明書或強型別的程式碼資料結構，徹底解決「文件與實作脫節」的痛點。
* **步驟四：在 CI 流程中嚴格驗證 (Validate in CI)**
  * 寫完程式碼後，透過靜態的 Registry Check 或是強大的 `live-check` (動態檢查)。
  * **Live-check 原理：** 在測試環境執行程式，Weaver 透過 OTLP 格式接收遙測資料，當場比對程式發出的資料是否符合步驟一的 Schema。不合規就會以 Exit code 1 擋下 CI 流程，阻止程式碼上線。
* *(加碼) 步驟五：AI 輔助重構 (Refactor)*
  * 如果 CI 失敗，利用 Weaver 內建的 MCP (Model Context Protocol) 伺服器，讓 AI 代理 (如 GitHub Copilot) 讀懂你的 Schema，自動幫你修改出合規的程式碼。

#### ⌨️ 第三階段：Weaver 核心指令總覽 (15 分鐘)

**【教學目標】快速走覽 Weaver 的主要指令，為下午與明天的實作預先鋪路。**

在終端機中，Weaver 所有的核心功能都圍繞在 `weaver registry` 這個命名空間下。講師將依序介紹以下關鍵指令：

* **定義與驗證類：**
  * `weaver registry check`：靜態驗證註冊表（你的 YAML 檔）語法與語義是否正確。
* **生成與演進類：**
  * `weaver registry generate`：根據模板產生程式碼或文件產出物。
  * `weaver registry update-markdown`：專門用來更新 Markdown 檔案中特定標記區塊的便捷指令。
  * `weaver registry diff`：比較兩個版本的 Schema 差異（未來討論 Schema 演進或發布破壞性變更時的關鍵工具）。
  * `weaver registry resolve`：將註冊表及其所有依賴的外部模組打包成一個單一檔案。
* **動態遙測與測試類：**
  * `weaver registry live-check`：即時監聽 OTLP 串流，對真實發出的遙測數據進行合規度檢查。
  * `weaver registry emit`：自己沒空寫程式？讓 Weaver 直接根據 Schema 產生「假遙測資料（範例訊號）」並發送給接收端，方便你先去畫儀表板 (Dashboards)。
* **AI 與擴充類：**
  * `weaver registry mcp`：啟動 MCP 伺服器以無縫對接 LLM 工具。
