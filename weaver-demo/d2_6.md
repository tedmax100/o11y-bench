### 🕒 第 6 小時：綜合戰鬥營 (Workshop) & 結業 Q&A

#### ⚔️ 第一階段：從無到有定義與生成 (20 分鐘)

**【教學目標】驗收學員是否能獨立完成 Schema 撰寫並成功生成強型別程式碼。**

* **實戰任務 1：定義一個全新的微服務 Schema**
  * **情境：** 講師請學員為一個「購物車 (Shopping Cart)」微服務定義遙測規範。
  * **動手做：** 學員需在專案內建立專屬的資料夾（例如 `telemetry/registry`）。接著撰寫 YAML 檔案，定義一個名為 `cart.add_item` 的 Span 以及一個計算加入購物車次數的 Metric。
  * **最佳實踐驗收：** 講師巡視並確保學員有將 Span 與 Metric 分開編寫，或是將共用屬性（如 `user.id`）獨立在 `common.yaml` 中供引用。
* **實戰任務 2：撰寫/套用模板並生成程式碼結構**
  * **套用模板：** 學員可以選擇自己手寫 Jinja2 模板，或是直接使用 OTel 社群現成的 Go 或 Java 模板。
  * **一鍵生成：** 學員在終端機執行 `weaver registry generate` 指令，將 YAML 規格書轉換成應用程式的程式碼。
  * **觀察成果：** 學員會看到 Weaver 自動將屬性名稱轉換成合適的常數（例如透過 `screaming_snake_case` 將其轉換為大寫底線分隔），並將 YAML 中的 `brief` 描述轉換為程式碼註解。

#### 💥 第二階段：實作、破壞與 CI 攔截 (20 分鐘)

**【教學目標】體驗「手動埋點的脆弱性」，並見證 Live-check 如何精準擋下錯誤。**

* **實戰任務 3：實作遙測發送邏輯**
  * **撰寫代碼：** 學員將剛才 Weaver 生成的強型別 API 匯入到自己的 Go 或 Java 應用程式中，並在「加入購物車」的商業邏輯中，呼叫這些 API 來記錄遙測訊號。
* **實戰任務 4：刻意破壞與 Live-check 攔截**
  * **刻意植入錯誤（Sabotage！）：** 講師請學員「故意」不使用自動生成的常數，而是手動打字，並刻意將指標屬性打錯（例如：Schema 定義為 `cart.item_id`，學員在程式碼裡故意寫成 `item_id`，漏掉前綴）。
  * **啟動 Live-check：** 學員執行 `weaver registry live-check` 指令，並設定監聽 OTLP 輸入源（例如 `--otlp-grpc-port 4318`）。
  * **發送與攔截：** 當學員執行這段帶有錯誤的程式碼並發出遙測訊號時，Live-check 會當場攔截，並以**退出代碼 1 (Exit Code 1)** 終止程序。
  * **解讀報告：** 學員檢視 Live-check 輸出的 YAML 報告，親眼見證 Weaver 精準指出「哪一個應用程式發出了不在 Schema 定義內的錯誤屬性」，完美模擬了在 CI 階段阻擋錯誤程式碼上線的情境。

#### 🤖 第三階段：AI 輔助重構救援 (10 分鐘)

**【教學目標】展現未來開發模式，讓 AI 根據 Schema 幫你擦屁股。**

* **實戰任務 5：使用 MCP 伺服器結合 AI 完成程式碼修正**
  * **啟動 MCP：** 面對剛才被 CI 擋下的錯誤程式碼，學員不需要手動回去查 YAML 文件。講師請學員在終端機輸入 `weaver registry mcp` 啟動 MCP 伺服器。
  * **AI 協作：** 學員打開 IDE，透過支援 MCP 的 AI 助手（如 GitHub Copilot 或 Claude Code），輸入 Prompt：**「幫我重構這段發送遙測的程式碼，讓它符合我們在 Weaver 裡的 OTel Schema 規範。」**
  * **修復完成：** AI 會讀取 Weaver MCP 提供的註冊表上下文，自動發現正確的屬性名稱應該是 `cart.item_id`，並瞬間將錯誤的程式碼替換為正確的型別安全寫法。

#### 🎓 第四階段：總結回顧與 Q&A 交流 (10 分鐘)

**【教學目標】收斂兩天的知識，為學員回到公司導入 Weaver 做好心理與技術準備。**

* **核心理念回顧 (Observability by Design)：**
  * 講師再次強調這兩天的核心精神： **將遙測訊號視為系統的一等「公開 API」** 。
  * 從今以後，指標與日誌不再是工程師隨性發揮的字串，而是具備版本控制、自動生成文件、並在 CI 流程中受到嚴格政策（Policy）與 Live-check 保護的工程資產。
* **開放 Q&A (Q&A 交流)：**
  * 開放學員提出在公司內部導入時可能會遇到的阻力（例如如何說服老員工放棄舊的埋點習慣）。
  * 探討未來的社群資源：鼓勵學員如果想深入了解或貢獻開源，可以加入 CNCF Slack 的 `#otel-weaver` 頻道與全球開發者交流。
* **頒發結業證明與大合照！**
