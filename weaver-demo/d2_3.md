### 🕒 第 3 小時：AI 輔助重構 (MCP Server 整合)

#### 🧗 第一階段：重構的挑戰與痛點 (15 分鐘)

**【教學目標】引發共鳴，探討嚴格 CI 防護下帶來的開發者負擔。**

* **痛點重現：**
  講師引導學員回顧上一個小時的 CI 阻擋機制。雖然我們成功擋下了錯誤的遙測代碼，但接下來呢？如果 CI 被 Weaver 擋下來了，工程師可能會覺得「天啊，又要手動改一堆程式碼...」。
* **手動重構的噩夢：**
  在傳統流程中，開發者必須：
  1. 仔細閱讀 CI 輸出的 `live-check` 報錯報告。
  2. 打開 YAML 規格書，尋找正確的指標或屬性名稱。
  3. 在廣大的程式碼庫中搜尋錯誤的命名，並手動逐一替換。
     這種在「規格書」與「程式碼」之間來回切換的過程不僅繁瑣，且很容易再次出錯。

#### 🔌 第二階段：啟動 MCP 伺服器 (20 分鐘)

**【教學目標】認識 Model Context Protocol (MCP) 並學會透過 Weaver 啟動整合服務。**

* **什麼是 MCP？**
  講師簡單介紹 MCP（模型上下文協定）。這是一種能讓大型語言模型（LLM）與外部工具（如本地端的檔案系統或資料庫）安全互動的標準協議。
* **Weaver 內建 MCP 支援：**
  Weaver 原生內建了 MCP 伺服器功能，專為 LLM 整合而生。它的作用是將你團隊辛苦寫出來的「遙測註冊表（Schema）」暴露並翻譯給 AI 工具看懂。
* **實作啟動指令：**
  講師請學員在終端機輸入以下指令啟動服務：

  ```
  weaver registry mcp
  ```

  執行後，Weaver 註冊表就會進入待命狀態，準備好將規格書內的上下文提供給接下來要連結的 AI 代理工具。

#### 🤖 第三階段：與 AI Coding Agent 協作實戰 (20 分鐘)

**【教學目標】體驗 AI 如何讀懂遙測規範，並自動修復未通過 CI 驗證的程式碼。**

* **連接 AI 程式碼助手：**
  講師示範如何將剛才啟動的 Weaver MCP 伺服器，與支援 MCP 的 AI 助手（例如 **GitHub Copilot** 或  **Claude Code** ）進行對接。
* **Prompt 驅動重構（實機演練）：**
  1. 講師打開剛剛在第二小時「故意寫錯、且被 CI 擋下來」的 Go 或 Java 程式碼。
  2. 呼叫 AI 助手，並輸入 Prompt 提示詞： **「幫我重構這段程式碼，讓它符合我們在 Weaver 裡定義的 OTel Schema 規範。」**
  3. **見證奇蹟：** AI 助手會透過 MCP 伺服器查詢 Weaver 註冊表，發現正確的屬性名稱應該是 `payment.order_id`，然後直接在編輯器內生成並替換掉錯誤的程式碼。
* **核心價值：**
  透過這種 AI 協作，繁重的重構任務可以瞬間完成。這不僅大大降低了導入嚴格規範的摩擦力，也讓團隊在享受「Observability by Design」好處的同時，省時又省力。

#### 🙋 第四階段：隨堂交流與 QA (5 分鐘)

**【教學目標】統整 MCP 應用，探討 AI 輔助在日常開發中的其他可能性。**

* **討論：**
  除了修復錯誤外，是否能在「一開始寫程式碼」的時候，就直接讓 AI 讀取 Weaver MCP 來生成帶有正確遙測訊號的基礎模板？
* **總結：**
  重構不再是一個令人頭痛的噩夢。將 CI 的「嚴格防護」與 AI MCP 的「無縫修復」結合在一起，我們就得到了一個幾乎全自動、高質量的遙測防護網！
