# 敘事稿（給 story-to-handdrawn-video 用）

- `day01-story.txt`：一隻 agent 被換到陌生環境，四次查詢全空，報出一個憑空生出來的數字。
- `day02-story.txt`：為什麼換一隻更聰明的機器人也沒用——它像一個非常聰明的新人，第一天上班。
- `day03-story.txt`：手轉旋鈕 vs. 牆上掛一張圖加一個守夜的，收在那塊沒有人翻給機器人看的牌子。
- `day04-story.txt`：推車翻了、紙條散在地上而全廠亮綠燈，收在「站在一塊有洞的地板上」。
- `day05-story.txt`：一本沒有人寫過的字典、一個只看名字的守衛，收在「沒有人能幫你抄下你想說什麼」。

主角沿用同一隻小機器人，`--character` 那段描述四天共用，這樣幾支影片放在一起才是同一個角色。

`day01-story.txt` 是把 Day1 抽成一條可以畫出來的敘事線：一隻 agent 被換到陌生環境、
四次查詢全空、最後報出一個精確到個位數卻是憑空生出來的數字。

**為什麼不直接餵 `day01.md`。** 那支工具吃的是中文敘事，會自動斷句成分鏡再生圖。
文章裡的 mermaid、PromQL、JSON、表格、終端輸出都會被當成句子，分鏡出來是一堆
畫不出來的東西。所以先抽敘事線，一句一個畫面。

## 稿子的寫法

- 一句一個分鏡，每句都要是**畫得出來的畫面**，不要抽象名詞堆疊。
- 數字用中文（八百一十四、六十、四點五），生成模型畫阿拉伯數字常常糊掉。
- 專有名詞盡量減到最少，`Prometheus / Loki / Tempo` 統一講成「指標、日誌、追蹤紀錄」。
- 收在一句結論上，不要收在數字上。

## 跑之前要有的東西

Node 20+、Python 3.10+、FFmpeg、Chrome 都要有（這台上都有）。
圖像生成需要 Codex Image2，或明確指定時吃 `OPENAI_API_KEY` —— **這台目前沒有設**，
那是唯一還缺的東西。

輸出是 1080×1440 直式無聲 MP4，適合社群短影音導流，不適合當文章內文插圖。

## 風格

那支工具有 20 種手繪風格。這個系列的調性是「所有輸出都是真跑出來的」，
選太可愛的風格會削弱可信度，建議挑版畫或鉛筆那類冷一點的。

## 概念日怎麼抽敘事線

Day1 有事故、有數字，故事線是現成的。Day2 是純概念日，沒有任何一次執行可以拍，
抽法是找那個**可以畫出來的比喻**：那本書把機器代理讀人類的觀測堆疊比喻成
「一個非常聰明的新人第一天上班」，整篇就掛在那句話上，三缺各給一個具體畫面
（大小寫、兩件事長得一樣、憑空的數字），最後收在「沒有人寫下來過」。

抽象的段落（認知瓶頸、決策級遙測的定義、可靠性怎麼衡量）一句都沒有進稿子。
它們是文章的骨架，但畫不出來。

Day3 更極端，整篇是 k8s operator，沒有一個名詞畫得出來。抽法是先找那個物理比喻：
一整片工廠、幾十台機器、有人走過去用手轉旋鈕（一次性 apply），對照牆上掛一張圖
加一個一圈一圈走的守夜的（CR 加調和迴圈）。`status.observedGeneration` 變成守夜的
身上那塊「我走到第幾版了」的牌子，最後收在跟 Day2 同一個地方——牌子一直都在，
只是沒有人翻過來給機器人看。

CRD、webhook、kustomize、GitOps、semantic convention 全部沒進稿子。它們是那天的
內容，但一個都畫不出來，而且塞進來會讓每一句都要先解釋名詞。

## 做第二天以後要記得的兩件事

**渲染輸出的檔名是固定的。** `--mode render` 一律寫到
`demo-services/story-to-handdrawn-video/out/picture_silent.mp4`，所以下一天一渲染
就把上一天蓋掉。渲染完馬上複製一份到這裡的 `out/`，檔名帶日號：

```bash
cp /home/nathan/Project/o11y-bench/demo-services/story-to-handdrawn-video/out/picture_silent.mp4 \
   /home/nathan/Project/o11y-bench/weaver-demo/ironman-2026/video/out/dayNN-picture_silent.mp4
```

那個 `out/` 不進版控，影片一支七 MB。

**角色表要沿用，不要重畫。** 每換一次標題就是一個新的 fingerprint 資料夾，
照流程會重畫一張角色表，機器人就會長得不太一樣。把前一天的
`00_character_reference.png` 複製到新資料夾再跑 `gen_images.py`，它會 skip 掉那一張，
於是所有場景參照的是同一張表。新舊資料夾的名字在 `--mode generate` 的輸出裡（
`prompts/generated/codex/<標題>-<fingerprint>`），對應的圖放在
`public/assets/generated/codex/<同名>/`。

## Day4 的抽法：實驗日只留那條曲線

Day4 有實驗、有數字，但畫面全在 YAML 跟 `kubectl` 裡。抽法是把「collector 收不下就被砍掉」
換成一個看得見的物理過程：紙條、箱子、一台推車、山上的倉庫。壓垮 = 換一台小推車，
crashloop = 翻了爬起來再翻，滑降的曲線（一千六百 → 一千三百 → 一千 → 零）原樣留著，
因為那是這一天唯一畫得出來又非留不可的數字。`memory_limiter` 變成推車上的一個秤，
它做的事只有一件：停下來，並且說出口。

沒進稿子的：webhook 注入、`PYTHONPATH`、`Instrumentation` CR 的欄位、sampler、
exit code 137、Java/PHP 的 annotation 差異。那些是文章的主體，但一個都畫不出來。

收尾故意跟 Day1 接回去——空結果的三種真相、以及那句「站在一塊有洞的地板上」，
讓四支影片是同一條線，而不是四則各自獨立的比喻。

## Day5 的抽法：概念日回頭接第一天那個猜錯的字

Day5 是 Weaver／registry，整篇是 YAML、Rego、CLI 輸出，一個名詞都畫不出來。抽法是
把 registry 換成一本**簿子**：一頁一個欄位，上面寫三件事（叫什麼、什麼意思、只能填
哪幾個字）。第三件事直接接回 Day1 那隻機器人猜錯的大小寫，讓這一天不是新開一個題目，
而是替第一天那個坑寫下解法。

policy 那段的畫面是一個**守衛**：它看起來在檢查東西，其實只在看名字開頭那兩個字，
換個開頭就放行——這是文章裡「檢查通過不等於東西是對的」那一節，唯一畫得出來的形狀。
改對規則之後在乾淨的 registry 上抓到兩個真的，那個意外收穫留著，因為它是全篇最有
說服力的一刻。

`infer` 的往返實驗收成結尾三句：名字抄得回來，意思、必不必填、值域抄不回來。
`userId` / `user_id` 變成「同一個客人被寫成兩個名字，中間多一個空格」。

沒進稿子的：manifest 結構、`ref` 跟 `extends` 的分工、`stats` 的數字、官方 registry
的一千個 group、白名單那段的簽名機制、三個指令的分工表。那些是文章的主體，但畫出來
只會變成一堆表格。
